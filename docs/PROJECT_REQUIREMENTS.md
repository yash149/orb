# Project and submission requirements

Based on the Fallen Docs screenshots supplied by the project owner. This is a checklist, not a claim that the requirements are complete.

## Project expectations

- Build one substantial, original hardware project.
- Choose a project that the creator can physically build and demonstrate.
- The supplied start page describes a program spanning approximately six weeks; check the portal for the current deadline rather than relying on a screenshot.

## Journaling

Journal once per work session. Useful entries include:
1. Date and title.
2. What happened.
3. What was worked on and what changed.
4. Why changes were made and what was learned.
5. Time spent in the session.
6. Genuine photos/screenshots of the work.

The screenshots say journals need not be formal or polished, but should show what was tried and accomplished. Entries should be the creator's own account.

## Submission types

The screenshots describe:
- **Design submission:** digital design is complete; after approval, project funding may be provided to build it.
- **Build submission:** the project has been built and works; after approval, it qualifies as a built project.

The supplied submission guidance says a project needs to be shipped before submitting it as a shipped project.

## README

Explain what the project is, how to use it, why it was made, and how it was made. Include relevant screenshots.

## Requested screenshots / visuals

- Full 3D assembly.
- PCB.
- Schematic or wiring diagram.
- Optional 3D render.
- Other useful visuals such as a poster, banner, or pinout diagram.

For a build submission, also include a demo video link and final product photos.

## Repository contents

- STEP files (.step) for each modeled part.
- Source project assembly (.f3d, .FCStd, or Onshape link), including electronics.
- PCB source files.
- For KiCad, the screenshots list at least .kicad_pro, .kicad_sch, .kicad_pcb, .kicad_prl, and gerbers.zip.
- Firmware.
- BOM CSV with a link to each item, including items already owned.
- Other relevant project materials such as libraries and references.
- For a build submission, keep source files up to date.

## Funding notes

The Project Funding screenshot says funding is based on project need, quality, polish, and complexity—not time spent or XP. The BOM should include the minimum quantity of each required component and bare-minimum tools. It should not include extra parts, unnecessarily expensive tools, modules/kits for parts the project is expected to design, or unrelated items.

The screenshots say to request only the funding amount needed. This repository setup does not submit a funding request.
